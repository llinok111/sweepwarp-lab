# sweepwarp-lab

**把 6 段 60 Hz 相机飞掠的「扫掠弦」从 17 条穿过/擦入几何（其中 11 条真的穿柱）降到 0 条，帧数不变；定速安全的替代方案要 455 帧，本方法最少 67 帧（−85.27%）。**

基线在仓库内可跑：`planNaive`（定速 60 Hz 播放，`bench/verify.mjs` 逐条复算）与
`minUniformFrames`（定速但整体减速到安全）都在 `src/core.mjs` 里，`bench/verify.mjs` 直接对照。

Upstream: none

## 是什么

相机沿一条折线路径飞掠一排立柱。逐帧位置之间是**直线弦**，只要某条弦离柱面比近裁剪半径
`r = 0.08` 更近，画面就会穿模。这个仓库做两件事：

1. **精确扫掠弦证书**：对每条弦解析计算「线段到三角形」的精确距离（Möller–Trumbore 命中 +
   端点到面 + 边到边，无采样、无绝对阈值），给出每条弦的最小间隙与穿模判定。
2. **按间隙密度的时间重参数化**：同一帧预算下，把帧在「间隙小」的地方堆密、在开阔处拉开，
   使每条弦都 ≥ `r`；并给出在这个密度族下的最少帧数。

## 怎么跑（一条命令）

```bash
node tools/gen-sample.mjs && node bench/verify.mjs
```

浏览器层（可选）：

```bash
python3 -m http.server 4173     # 然后打开 http://localhost:4173
```

`index.html` 用固定版本 `three@0.169.0` 的 importmap，无打包、无 `node_modules`、无浏览器自动化。
页面上的帧数 / 最小间隙 / 违反条数都由 `src/core.mjs` 实时算出，与 node 断言同源。

## 证据（全部来自 `bench/result.json`，`node bench/bench.mjs` 重跑）

| 量 | 值 |
| --- | --- |
| 场景 / 三角形 | 6 / 720 |
| 定速 60 Hz 同帧预算（基线 `planNaive`）| 203 帧中 **17 条弦违反**，其中 **11 条真正穿过几何** |
| 间隙密度重参数化（同帧数）| 203 帧，**0 违反**，最小扫掠间隙 **0.1220 m**（半径 0.08）|
| 最少帧（`planAdaptive`）| **67 帧** |
| 定速安全（`minUniformFrames`）| **455 帧** = 预算的 **2.241×** |
| 相对定速安全的帧数削减 | **85.27%** |
| 规划耗时（6 场景合计，grid=800）| cold **26.33 ms**，median **24.73 ms**，min 24.38，p95 25.81，stddev 0.45（rel 1.81%，11 samples × 8 reps）|

`node bench/verify.mjs` → `RESULT PASS failures=0`，逐条打印实测值：

- **精确性**：240 条随机弦上，解析距离与独立采样 oracle 的最大差距 `1.951e-4`（弦弓高量级），
  且解析值从不超过采样下界。
- **独立 oracle**：36 条最紧的证书弦各再采 64 点（另一套「平面投影 + 叉积重心符号 + 边夹取」实现），
  最小采样间隙 `0.12197` = 解析最小值，**0 点低于半径**。
- **尺度不变性**：同一几何缩放到 `1e-6 / 1e-3 / 1 / 1e3 / 1e6`（共 30 次重放），
  帧数与「是否违反」判定 **0 不一致**，相对最小间隙漂移 `5.4e-14`。
- **确定性**：同一场景跑两次，帧数与逐帧坐标**逐位相同**。

## 已知限制

- 运动是**折线上的直线弦**（逐帧线性插值），不是样条；证书只覆盖这两帧位置之间的扫掠段。
- 只有箱体近似为多边形柱体的**静态**几何；不含旋转物体、蒙皮、动态障碍。
- 唯一涉及的常数是 MT 的**相对平行判据** `|det| ≤ 1e-12·|e1|·|e2|`（无量纲）与网格分辨率
  `grid=800`；**没有绝对长度阈值**，因此有效尺度覆盖 `1e-6 … 1e6`（见上表尺度实测）。
  若把网格细化到弦长小于 MT 判据能分辨的尺度，证书会退化——README 认为该边界在 1e-6 以下。
- 场景是合成语料（固定种子 `20261114`），不是真实 glTF 资产；生成器
  `node tools/gen-sample.mjs` 两次运行字节一致（md5 `4af4137b4314732bc5095320ebf20331`）。
- 「最少帧」只在该「间隙密度 » 1/max(clearance−r, floor)」族内贪心最少，不是全局最优时间重参数化。

## 本轮创新

**新在「把逐帧扫掠弦的精确三角距离做成 60 Hz 时间预算的证书，并用间隙密度反解时间重参数化」。**
与同账号的 `toi-cert-lab`（只做移动三角对之间的 TOI 区间）和 `labelcast-lab`（只做静态标签布局）
不同：这里把「相机运动的每一段扫掠」当作可判定的几何对象，在同一帧预算下同时给出
「哪些弦穿模」与「如何重新分配时间使全部弦不穿模」，且该结论可由 node 在
`1e-6…1e6` 尺度上逐位复算。以前的同类作品只给静态布局或单帧碰撞，没有「同预算
时间重参数化 + 逐弦证书」这一组合，因此不是换皮。

## 结构

```
index.html            # importmap + 面板（three 0.169.0 固定版本）
main.js               # 只做渲染与交互，数值全部来自 core
src/core.mjs          # 纯 ES module：精确线段-三角形距离、三种时间规划、独立 oracle
tools/gen-sample.mjs  # 确定性生成 data/scenes.json
bench/verify.mjs      # G4 断言（精确性 / 证书 / oracle / 尺度 / 确定性）
bench/bench.mjs       # 冷启动 + 11 样本计时 -> bench/result.json
```
